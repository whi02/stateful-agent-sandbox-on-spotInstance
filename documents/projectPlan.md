# 프로젝트 계획과 진행도

Spot 100% research 프로젝트가 어디까지 왔고 다음에 무엇을 해야 하는지 사용자와 Claude Code가 같이 확인하는 문서입니다. 작업 흐름은 `songmhT-taskDocs/`의 CFP와 예시 제안서에서 가져왔고, CFP의 제약 사항은 이 문서에서 판단하지 않았습니다.

## 요약

- **주제 (확정):** 상태를 가진 AI Agent 실행 환경(샌드박스)을 Spot 인스턴스 100%로 운영합니다. 컨테이너 기반으로 하고, 모델은 호출하지 않고 기록해 둔 에이전트 실행 기록을 재생해 워크로드를 만듭니다. 상태 보존 수준 4가지(처음부터 재실행 / 기록만 / 기록+파일 / 파일+실행 중 프로세스 전체)를 실제 AWS Spot 회수 환경에서 On-Demand와 비교합니다. 선생님 피드백(2026-10-16, `SongmhT.md`)에 따라 "MCP 도구 실행환경이 Spot에서 운영되는 관점"에서 시작하고, 직관적인 것부터 단계적으로 올립니다. 제목은 "상태를 가진 AI Agent 실행 환경의 Spot 100% 운영: 상태 보존 수준별 비용·성능 측정"로 확정했습니다(2026-10-26). 범위는 2.3.5에서 확정합니다.
- **목표 (확정, 채택 2026-10-16):** 상태를 가진 AI Agent의 실행 환경을 On-Demand에서 Spot 인스턴스로 옮겨 인프라 비용을 줄이면서, 실제 회수 상황에서도 성능이 얼마나 유지되는지 측정하는 것.
  1. AI Agent의 실행 환경(샌드박스)을 Spot에서 운영한다.
  2. 작업 완료율, 완료 시간, 복구 시간이 On-Demand와 얼마나 다른지 측정한다.
  3. 인프라 비용과 회수 때문에 늘어난 비용(저장, 복구)을 합친 총비용을 On-Demand와 비교한다.
  4. 상태 보존 수준별로 비교하고, 실제 회수(FIS) 환경에서 한다.
- **하지 않는 것 (선생님 피드백):** LLM 서버(모델 서빙)를 Spot으로 올리기, SPS 같은 가용성 신호 분석(예측, 풀 단위 조기 경보). 업그레이드 후보입니다.
- **기간:** 목표 종료 2026-11-08(일), 최종 마감 2026-11-30(월, 필수). 구간은 아래 "큰 일정"에 있습니다.
- **예산:** AWS 비용 $200 이하를 목표로 합니다. AWS 비용만 지원받고 LLM 비용은 없습니다.
- **현재 단계:** M2(제안서) 마지막 날. 선행 작업(0), 필수 강좌(1.1), 고려 사항(`spotConsiderations.md`), 목표·AI Agent 범위(2.1.4~2.1.5)를 확정했습니다. M1에서 계획했던 지표·Scope 확정(2.3)은 아직 남았습니다.
- **다음 할 일:** 2.3 지표·Scope 확정, 2.2.2 문제 정의 초안 보완(사용자), 2.4.1·2.4.2 결정, 2.1.3 트랙, 일정 조정.
