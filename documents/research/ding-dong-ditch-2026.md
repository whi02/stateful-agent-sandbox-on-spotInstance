# Ding-Dong Ditch: Peeking Into Spot Instance Availability (2026)

> 노션 북마크 제목은 "arxiv.org"로만 표시됩니다. 같은 노션 묶음의 다른 두 자료(SpotLake, HPDC'25)와 같은 연구실 논문이고, 이전 대화에서 이 PDF 주소를 소개했으므로 이 논문으로 판단했습니다.

## 한 줄 요약

Spot 요청을 넣고 **AWS가 받아들이는 순간 바로 취소**해서(초인종 누르고 도망가기), 인스턴스 요금을 거의 내지 않고 Spot 가용성을 3분 간격으로 관측하는 방법입니다. 실제 회수 2,635건을 분석하니 **같은 인스턴스 타입·같은 AZ의 동시 회수는 92.9%가 3분 안에** 일어났습니다. 이 신호로 60분 뒤까지의 가용성을 F1 0.85 이상으로 예측했습니다.

## 방법

- Spot 요청의 결과(용량이 있는지)는 인스턴스가 running이 되기 **전에** 정해집니다. 그래서 요청이 받아들여져 프로비저닝이 시작되면 바로 취소합니다.
- 결과는 "가능 / 불가능" 이진값입니다. 한 시점에 요청을 여러 개 동시에 넣으면 확보 가능한 수량도 추정할 수 있습니다.
- 수집기, 특징 계산, XGBoost 예측을 서버리스(Lambda)로 구성했습니다.

## 규모

- AWS와 Azure, 인스턴스 타입 68개, 리전 15개
- Spot 요청 총 336,033건
- 실제로 실행한 인스턴스의 회수 이력을 동시에 모아 비교했습니다.

## 핵심 수치

| 항목 | 값 |
|---|---|
| **같은 타입·AZ 동시 회수 간격** | **85% 이상이 1분 이내, 92.9%가 3분 이내** (회수 2,635건) |
| 24시간 관측 비용 | 실제 인스턴스 계속 실행 $548.83, 기존 주기적 probing(10분) 추정 $5.49, **DDD(3분) $2.20** |
| 비용 비율 | 계속 실행 대비 249.5배, 기존 probing 대비 2.5배 저렴 |
| DDD 신호 대 실제 실행 대수 (AWS) | 같음 77.12%, 실제가 더 많음 22.31%, 실제가 더 적음 0.56% |
| DDD 신호 대 실제 실행 대수 (Azure) | 같음 88.68%, 실제가 더 많음 11.03%, 실제가 더 적음 0.30% |
| 현재 가용성 모델링 | F1-macro 최대 0.90 |
| 예측 (3~60분 뒤) | 60분 뒤에도 F1-macro 약 0.85 |
| TPC-DS 시뮬레이션 손실 계산량 | 예측 없이 실행 대비 3분 예측 27% 감소, 15분 예측 최대 46% 감소 |

- DDD 신호는 **보수적**입니다. 새 요청 승인이 이미 실행 중인 인스턴스 유지보다 용량 변화에 더 민감하기 때문입니다. 그래서 "DDD로 확보 가능"이면 실제로도 가능할 가능성이 높아 하한 지표로 쓸 수 있다고 봅니다.
- 예측 기간을 늘리면 손실은 줄지만 오탐 때문에 작업을 미루는 유휴 시간이 늘어납니다.

## 프로젝트에 주는 것

- **"동시 회수"가 같은 용량 풀(인스턴스 타입 + AZ) 단위로 몰려 일어난다**는 정량 근거입니다. 한 노드가 회수되면 같은 풀의 다른 노드도 곧 회수될 가능성이 매우 높습니다. 인스턴스 타입과 AZ를 섞어야 하는 이유입니다.
- 2분 알림보다 훨씬 이른 **3~60분 앞의 가용성 예측**이 가능하다는 근거입니다. 상태 있는 워크로드를 미리 옮기거나 체크포인트를 미리 만드는 설계에 연결할 수 있습니다.
- 관측 비용이 하루 몇 달러 수준이라 개인 프로젝트에서도 따라 할 수 있는 규모입니다.

## 한계와 주의점

- 심사 전 arXiv 버전입니다. 학회 게재는 확인하지 못했습니다.
- 예측 평가는 배치 분석(TPC-DS) 시뮬레이션입니다. 웹 서비스나 에이전트 같은 대화형 워크로드에서는 평가하지 않았습니다.
- 논문도 짧은 간격의 반복 요청이 클라우드 API 사용 한도와 용량 할당에 영향을 줄 수 있다며 윤리적 고려를 언급합니다. 따라 할 때는 API 한도 안에서 해야 합니다.

## 인용할 때 쓰는 표현

- "Ding-Dong Ditch(2026)가 분석한 실제 Spot 회수 2,635건에서, 같은 인스턴스 타입·같은 AZ의 동시 회수는 92.9%가 3분 안에 일어났다."
- "DDD는 Spot 요청을 승인 직후 취소하는 방식으로, 실제 인스턴스를 계속 띄우는 관측보다 249.5배 저렴하게 가용성을 관측했다."
